### 02 · Creator OPS（红人运营工作台 / KOL Workspace）

* **此前 GPT 写错的地方**：
  1. 角色标签写成「业务规则 · 产品设计 · 验收」，听起来像只写文档点测试的纯 PM/QA，严重削弱个人落地能力。
  2. 写得像个空壳原型或普通自动回复机器人，并且到处塞满“尚不能确认稳定实现”“并非全部投入生产”这类防御性免责声明。
* **真实项目事实**：
  * **起源与业务量级**：作者在一线亲自负责海外红人营销全流程（筛选、邀约、沟通、预约协调、确认预约、到店履约、内容交付、素材回收、二次剪辑、运营管理共 10 个环节；业务目标为每月推动约 20 位 KOL 发布内容、每周用回收素材产 3 条品牌 Reels）。
  * **核心瓶颈**：人工注意力被大量低价值信息中转消耗——频繁手动刷 Instagram 查新消息，在 KOL、客服、门店三方之间当传话筒；信息散落在私信、客服群和表格里；大量业务规则全靠人脑硬记，且已确认预约常被门店临时改期。
  * **真实落地的工程方案**：
    * **业务知识库**：将原本靠人脑记忆的规则整理成 **12 份结构化 Markdown 知识库文件**（涵盖合作政策、交付标准、门店与项目菜单、预约流程、英文回复规范、押金/取消/改期规则与人工介入条件；例如仅 Box Hill 门店、仅工作日且最晚 17:00、一次一人一项目、40 澳元可退押金、Reel 与 Tagged Post 要求）。
    * **浏览器自动化**：受限于 Meta 官方 API 权限，采用桌面浏览器路线（`AppleScript → Chrome JavaScript → DOM`）直接操作 Meta Business Suite，跑通了定时轮询新消息、读取网页 DOM、提取合作需求及发送私信。
    * **核心架构理念**：**确定性程序负责执行**（轮询、去重、DOM 读写、发送、结果校验），**AI Agent 负责理解与判断**（语义理解、需求提取、调用知识库、草拟回复、识别异常）。
  * **关键产品转折**：跑通私信自动收发后，意识到单纯做个自动回复 Chatbot 没什么意思，于是转向 **以业务状态为中心的红人运营工作台（KOL Workspace）**。将非结构化私信抽成 9 步状态机（`表达意向 → 选项目 → 提供时间 → 客服排期 → 押金 → 预约成功 → 到店履约 → 发布检查 → 素材归档`），把待办队列、阶段看板、KOL CRM、知识库和 Agent 执行收进同一界面。
  * **真实进展边界**（自信、诚实表述，不要写免责声明）：12 份知识库、定时轮询、DOM 私信读取、需求提取、规则驱动英文回复生成和浏览器发送均已跑通；客服与 KOL 之间的全自动双向沟通及自动改期仍在持续完善，高风险变更与退款默认转人工拍板。
